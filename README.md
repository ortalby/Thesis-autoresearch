# מערכת תזות השקעה עם לולאת autoresearch

המערכת עוקבת אחרי כ-1,125 מניות (Russell 1000 ות"א-125) ומעדכנת לכל אחת תזת השקעה בעברית.
העדכון מבוסס על דוחות, דיווחים, חדשות, מתחרים, מאקרו ומחירים, והתוצאות נכתבות ל-Google Sheet.
במקביל רצה לולאת מחקר בסגנון autoresearch של קארפתי, שמשפרת כל הזמן את הקוד שכותב את התזות. שיפור נשמר רק כשהוא מעלה ציון מדיד.

> המערכת היא כלי מחקר ואינה ייעוץ השקעות.

## איך הלולאה של קארפתי ממופה לכאן

| autoresearch המקורי | כאן |
|---|---|
| `program.md`: הנחיות שאדם כותב | `program.md`: כיווני מחקר ואיסורים לסוכן |
| `train.py`: הקובץ היחיד שהסוכן משנה | `strategy.py`: איך בונים את ההקשר, כמה שלבים, איך מכיילים תחזיות |
| `prepare.py`: תשתית ומדידה קבועות | `engine/`: איסוף נתונים, סכמת התזה, השופט והציון. הסוכן לא נוגע בהם |
| ריצת אימון של 5 דקות ו-val_bpb | הערכה על סט קבוע של זוגות (מניה, תאריך) מאחרי תאריך הידע של המודל |
| שומרים רק שיפור (ratchet) | ציון גבוה יותר ב-`min_improvement` מוביל ל-commit. אחרת `strategy.py` חוזר לגרסה הקודמת |

**הציון המשולב** (`engine/metrics.py`):
- 35% **מתאם דירוג** (Spearman) בין התשואה העודפת החזויה לבפועל, ל-30 ול-90 יום. המדידה נעשית בכל תאריך בנפרד.
- 35% **Brier skill**: עד כמה ההסתברות להכות את המדד מכוילת יותר מ-0.5.
- 30% **שופט**: מודל שמדרג ביסוס בנתונים, שלמות, עקביות, הפרכה ואיזון סיכונים. אם התזה "יודעת" משהו מהעתיד, הציון שלה מתאפס.

**מניעת דליפת מידע מהעתיד:**
- כל נתון בחבילה מסונן לפי תאריך הפרסום שלו: נכנס רק מה שפורסם לפני תאריך הניתוח.
  - דוחות SEC ועובדות XBRL לפי תאריך ההגשה.
  - דיווחי מאיה לפי מועד הפרסום.
  - חדשות לפי תאריך, דרך מסנני `after:` ו-`before:` של Google News.
  - מאקרו לפי מועד הפרסום המקובל של כל סדרה.
  - דוחות כספיים של חברות ישראליות לפי המועד החוקי להגשה: 60 יום לרבעון, 90 יום לדוח שנתי.
- תאריכי ההערכה מתחילים אחרי תאריך הידע של המודלים (מרץ 2026), כדי שהמודל לא "יזכור" את התוצאה.
- `strategy.py` נבדק סטטית לפני כל הרצה: בלי גישה לקבצים, לרשת או לתכונות פרטיות (`engine/guard.py`).

## ▶️ ⏹️ הפעלה ועצירה של הבוט

כל עוד ה-secrets לא הוגדרו, הריצות המתוזמנות מדלגות בשקט, בלי כישלונות ובלי מיילים.

**בטלפון:** אפליקציית GitHub ← ה-repo ← Actions ← **"שליטה בבוט"** ← Run workflow ← בוחרים:
- **התחל:** בודק שכל ה-secrets קיימים, מפעיל את הריצות המתוזמנות ומריץ עדכון מיד.
- **עצור:** מכבה את הריצות המתוזמנות ומבטל ריצות פעילות. התזות שכבר נשמרו נשארות.
- **מצב:** מציג אם הבוט פועל ומה רץ לאחרונה.

קישור ישיר, כדאי לשמור כסימנייה: https://github.com/ortalby/Thesis-autoresearch/actions/workflows/control.yml

## מה רץ ומתי (GitHub Actions)

- **עדכון תזות** (`update.yml`, כל יום ב-04:23 UTC):
  1. מודד תחזיות שהגיע זמנן.
  2. מזהה אירועים: דוח SEC חדש, דיווח מאיה, תנועת מחיר חריגה או תזה ישנה.
  3. מרענן את המניות בעדיפות הגבוהה ביותר ומפרסם ל-Sheet.
  - בהתחלה אין תזות בכלל, ולכן כיסוי מלא של כל המניות לוקח כמה ימים. הקצב נקבע לפי `max_theses_per_run`.
- **לולאת מחקר** (`research.yml`, כל יום ב-14:37 UTC):
  - בריצה הראשונה היא בונה ומקפיאה את סט ההערכה. זה לוקח זמן ונעשה פעם אחת.
  - אחר כך היא מריצה `experiments_per_run` ניסויים.

שני ה-workflows שומרים את המצב בתיקיית `state/` ב-repo: תזות, היסטוריה, תחזיות ויומן ניסויים.

## התקנה

1. **Repo ב-GitHub:** פתחי repo חדש והעלי אליו את כל הקבצים.
   - ה-repo צריך להיות **ציבורי** כדי שדקות Actions יהיו בחינם. ב-repo פרטי יש 2,000 דקות בחודש, והריצות היומיות יחרגו מהן.
   - התזות עצמן יופיעו בתיקיית `state/`, אבל ה-secrets נשארים מוסתרים.
2. **מפתח Gemini:** ב-[Google AI Studio](https://aistudio.google.com/apikey), מפרויקט שאין בו חיוב.
3. **SEC_USER_AGENT:** שם ואימייל, לדוגמה `Ortal Research ortal@example.com`. SEC דורשת אותם בכל בקשה.
4. **Google Sheet:**
   1. ב-Google Cloud Console: פרויקט, הפעלת Google Sheets API, יצירת Service Account ומפתח JSON.
   2. צרי גיליון ריק ושתפי אותו עם כתובת ה-Service Account בהרשאת עריכה.
   3. את ה-ID של הגיליון מעתיקים מה-URL (החלק שבין `/d/` ל-`/edit`).
5. **Secrets** ב-Settings → Secrets and variables → Actions:
   `GEMINI_API_KEY`, `SEC_USER_AGENT`, `GOOGLE_SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_JSON` (כל תוכן קובץ ה-JSON).
6. **הרצה ראשונה:** ב-Actions → "שליטה בבוט" → Run workflow → **התחל**.

הרצה מקומית (עם אותם משתני סביבה):
```bash
pip install -r requirements.txt
python -m pytest -q tests
python run_update.py --max 5 --no-sheets
python run_research.py --experiments 1
```

## הגיליון

- **תזות:** שורה לכל מניה. כוללת עמדה, ביטחון, תשואה עודפת צפויה, הסתברות, תזה, עסק, פיננסים, תחרות, מאקרו, תמחור, דיווחים וחדשות, קטליזטורים, סיכונים, מה יפריך את התזה, מה השתנה וסיבת העדכון.
- **יומן שינויים:** כל עדכון, עם העמדה הקודמת והחדשה.
- **ביצועי תחזיות:** מדידה חיה של התחזיות שהגיע זמנן, לפי אופק ולפי גרסת אסטרטגיה.
- **מחקר:** כל ניסוי של הלולאה, עם הציון ועם התוצאה (נשמר, נדחה, קרס או נפסל).

## עלות: אפס

ברירת המחדל מוגדרת לחינמי לגמרי:
- **Gemini:** מפתח מפרויקט שאין בו חיוב ב-AI Studio. כך Google לא יכולה לחייב, וכשהמכסה היומית נגמרת, הריצה פשוט נעצרת וממשיכה למחרת.
  - התזות והשופט רצים על `gemini-3.5-flash-lite`, עם מכסה חינמית של כ-500 בקשות ביום.
  - הסוכן של לולאת המחקר רץ על `gemini-3.8-flash` עם מכסה נפרדת. הוא צריך רק כמה קריאות ביום.
- **GitHub Actions:** חינמי ב-repo ציבורי.
- **מקורות הנתונים** (SEC, מאיה, הבורסה, בנק ישראל, הלמ"ס, FRED, Google News, yfinance) חינמיים.

מה זה אומר בפועל:
- עד 150 תזות ביום, ולכן הכיסוי הראשון של כל 1,125 המניות לוקח כ-8 ימים. אחר כך המערכת מעדכנת לפי אירועים.
- שני ניסויי מחקר ביום, על סט הערכה של 24 דגימות ועוד 12 לבקרה.
- כל הקריאות נספרות מול `max_calls_per_day: 450` ב-`config.yaml`.

**לפני ההפעלה**, כדאי לבדוק את המכסות האמיתיות של הפרויקט ב-[aistudio.google.com/rate-limit](https://aistudio.google.com/rate-limit) ולעדכן את `max_calls_per_day` ואת `requests_per_minute`. Google לא מפרסמת מספרים קבועים.

**שני דברים שכדאי לדעת על החינמי:**
- בחינם, Google רשאית להשתמש בפרומפטים כדי לשפר את המוצרים שלה. בפרומפטים יש רק נתונים ציבוריים: דוחות, חדשות ומחירים.
- `flash-lite` חלש יותר מ-`3.8-flash`, ולכן התזות פחות מעמיקות. לולאת המחקר נועדה בדיוק בשביל זה: לשפר את התוצאה מתוך המודל הזה.

## מגבלות חשובות

- **מאיה ו-api.tase.co.il** הם ממשקים לא רשמיים מאחורי WAF. המערכת פונה אליהם כמו דפדפן ובקצב נמוך, אבל הבורסה יכולה לשנות אותם בכל רגע. הממשק הרשמי הוא TASE Data Hub, והוא בתשלום.
- **yfinance** גם הוא לא רשמי. דוחות כספיים ישראליים זמינים בו רק לכ-5 רבעונים אחרונים.
- **תיאור הפעילות של חברה ישראלית** ממאיה הוא מידע עדכני בלי תאריך פרסום, ולכן הוא נכנס רק לתזה החיה ולא לסט ההערכה.
- **סט ההערכה קטן** (24 דגימות לפיתוח ו-12 לבקרה, בגלל המכסה החינמית), ולכן הציון רועש. ציון הבקרה ב-`results.tsv` מראה אם שיפור באמת מכליל.
- **השופט הוא אותו מודל** שכותב את התזות. אפשר להחליף ל-`judge_model` אחר ב-`config.yaml`.
- **אם מחליפים את מודל התזות**, צריך לעדכן גם את `leakage_cutoff` לתאריך הידע של המודל החדש.
